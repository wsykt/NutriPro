## 四、综合结论与建议

### 4.1 优化效果

- **健康咨询对话（最复杂场景）**: 优化前触发 fallback（30s 超时），优化后 Ollama 直调成功，实际耗时 **51.6s**
- **总体本地成功率**: 4/4 (100%，优化前为 3/4 + 1 fallback)
- **本地平均耗时**: 31.7s（优化后反而更稳定，无 fallback）

### 4.2 核心差异

| 维度 | 云端 DeepSeek | 本地 Ollama 7B (qwen2.5 q4_k_m) |
|------|-------------|--------------------------------|
| 平均响应 | 9.6s | 31.7s |
| 平均字数 | 1450 | 1116 |
| 健康咨询响应质量 | 更结构化(分6点)，引用具体指南名 | 更简洁(分5点)，建议准确但未引来源 |
| 结构化 JSON 稳定性 | 无重复语句 | 偶有模式重复（如运动方案中游泳/跑步重复句式） |
| 数值准确性 | 孕期总热量 2250 卡更保守 | 2500 卡略偏高 |
| 并发能力 | 高（云端弹性扩容） | 低（单卡串行~3人并发） |
| 成本 | 按 Token 计费 | 零边际成本（仅电费） |
| 隐私 | 数据上云 | 完全离线 |

### 4.3 超时建议

基于实测耗时（最长 52s），OLLAMA_TIMEOUT 可设为：
- **保守值：60s**（覆盖健康咨询 51.6s + 余量，推荐日常使用）
- **均衡值：45s**（除最长场景外全覆盖，需可接受 fallback）
- **极限值：90s**（防止偶发长任务失败，开发/测试环境）

### 4.4 下一步优化建议

1. **知识库精简（用户第4点）**：本地模式下，知识库检索 top_k 从 5 降到 3，或针对本地 LLM 裁剪 prompt 长度
2. **输出去重**：结构化 Agent 中加入重复句式检测后再 JSON 校验（对 qwen2.5-7b 输出做轻量去重）
3. **混合路由**：根据 prompt 复杂度（长度、是否含知识库检索结果）动态选择云端/本地——简单任务走本地省成本，复杂任务走云端保质量
4. **num_ctx 调优**：如果 8192 实际显存占用仍低，可提升到 10240/12288，进一步降低截断风险
