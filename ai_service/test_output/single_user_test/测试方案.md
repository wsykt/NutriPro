# 单用户本地真实环境测试方案

生成时间: 2026-08-09

---

## 一、测试目标

在**本地单用户真实环境**下，验证个人健康助手 AI 服务的 4 个核心咨询功能，并**并行推进脚本测试与真实环境测试**两种方式，输出可复现的测试过程与结果报告。

| 目标 | 说明 |
|------|------|
| 功能可用性 | 4 个 AI 功能在正常/高性能两种模式下均能返回合规结果 |
| 模式路由正确性 | 模板命中→A方案(本地改写)；未命中→C方案(云端/回退)；high_performance=true→直接C方案 |
| 提示词模板固化 | 每个功能仅保留一份提示词模板，测试时只替换输入参数 |
| 脚本参数化 | 爬虫/知识库/模板生成脚本只需改关键词、数量即可自动运行 |
| 双链路自动连接 | 本地 Ollama + 云端 DeepSeek 由启动脚本自动探测连接 |

## 三、测试范围与用例矩阵

4 功能 × 2 模式 × 2 类用例（模板内/模板外）核心矩阵：

| 编号 | 功能 | 场景 | 模式 | 预期路由 |
|------|------|------|------|----------|
| 1 | 健康问答 | 模板内-减脂 | normal | A_template_local 或 C_fallback |
| 2 | 健康问答 | 模板外-新方向 | normal | A/C（新方向检索相似） |
| 3 | 健康问答 | 任意 | high_performance | C 云端直出 |
| 4 | 一日饮食方案 | 模板内-控糖 | normal | A_template_local |
| 5 | 一日饮食方案 | 模板外-新方向 | normal | A/C |
| 6 | 一日饮食方案 | 任意 | high_performance | C 云端直出 |
| 7 | 食材菜谱推荐 | 模板内-增肌 | normal | A_template_local |
| 8 | 食材菜谱推荐 | 模板外-新方向 | normal | A/C |
| 9 | 食材菜谱推荐 | 任意 | high_performance | C 云端直出 |

### 功能① 健康咨询问答 (qa)

**A 方案本地改写模板：**

```text
你是健康科普改写助手。请基于提供的知识库标准回答模板，结合用户实际问题进行个性化改写。

{user_derived_context}

{template_content}

```

## 五、输入输出记录规范

每次测试调用统一记录以下字段（脚本自动生成 JSON 结果文件）：

| 字段 | 说明 |
|------|------|
| case_id | 用例编号（如 01_qa_高血压_减脂） |
| label | 场景标签（模板内/模板外/高性能） |
| in_template_expected | 是否期望命中模板 |
| func | 功能标识（qa/diet_plan/food_recommend/exercise） |
| route | 实际路由（A_template_local / C_fallback / C_high_perf） |
| mode | normal / high_performance |
| request | 完整请求体（输入） |
| valid_passed | 校验是否通过 |
| valid_issues | 校验未通过项列表 |
| recall_sim | 模板召回相似度 |
| elapsed_sec | 总耗时（秒） |
| timing_ms | 各阶段耗时（retrieve/local_rewrite/cloud_fallback/total） |
| response | 完整响应（输出） |
| error | 异常信息（null 为正常） |

## 六、执行方式

### 6.1 脚本测试（并行执行）

直接调用 `services/mode_router.py` 的 ModeRouter 接口，全量 12 用例执行，记录输入输出与路由。命令：

```bash
python run_single_user_script_test.py
```

### 6.2 真实环境测试（并行执行）

启动 AI 服务后，通过 HTTP API 调用 4 个功能（每功能 2 个代表用例），记录真实输入输出与耗时。命令：

```bash
python run_single_user_real_test.py
```

### 6.3 并行推进

两条测试线互不依赖，可同时运行。完成后合并输出《测试报告》。
